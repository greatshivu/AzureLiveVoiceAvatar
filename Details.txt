How it works

Each entry in PAGES declares: route, aliases (how users name it by voice), controls (any mix of text/select/radio/checkbox/date-range with their query params + option/synonym words), table columns, a speakRow (read-out), and hints.
Generic rendering: SearchPage.jsx + DynamicFilterBar.jsx + useSearch.js build any page from that config; App.js and Navbar.jsx generate routes/links from it.
The avatar analyzes the same registry at runtime: parseCommand scores the utterance against every page's aliases (weight 3) and control-option words (weight 2) to pick the target page, then extracts each control's value from the words spoken. So "electronics in stock" said on the Orders page auto-navigates to Items and applies Electronics + in-stock; "read the top invoice" would work the moment an Invoices page is added.
